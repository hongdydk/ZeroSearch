# 손님 1차(L1) 브라우즈

구매자 홈·카테고리 입구는 **게스트 1차 15개**(쿠팡식 겹침 멀티 태그)다. AI-Hub 대분류(`table_taxonomy`)는 등록·관리자 힌트로 남긴다.

태그 자동 규칙 SSOT: [guest-l1-tag-rules.md](./guest-l1-tag-rules.md)

## 15개 1차 (이름 고정, 겹침 허용)

1. 생수/음료
2. 커피/원두/차
3. 과자/초콜릿/시리얼
4. 라면/면류
5. 통조림/캔
6. 반찬/간편식/대용식
7. 국/탕/찌개
8. 즉석밥/볶음밥
9. 죽/스프
10. 분식/만두/피자
11. 짜장/카레/돈까스
12. 냉장/냉동/간편요리
13. 가루/조미료/오일
14. 장류/소스
15. 유제품/아이스크림

신선(과일/채소/수산/정육)은 게스트 1차에 두지 않는다. **보관(상온/냉장/냉동)** 은 1차 화면의 필터다. 12번만 냉장·냉동 간편요리 **입구 이름**이다.

## 축 흐름

1. 홈에서 1차를 고른다.
2. **브랜드부터** / **메뉴부터** / **판매자 오퍼** 토글 — 누르면 바로 바뀐다. 확인 버튼 없음. 1차마다 기본 축은 브랜드 또는 메뉴여도 순서를 잠그지 않는다.
3. 브랜드·메뉴 목록은 **그 1차 태그가 붙은 카드만**. 고르면 회사+품목 카드(identity collapse). 같은 회사의 근사 중복 제목(반복 접미)은 엔진이 한 장으로 접는다. 제조사가 다르거나 핵심 명사가 다른 품목은 접지 않는다. L1 범위·`axis=seller`(가게 리스팅마다 한 장)는 그대로다.
4. **판매자 오퍼**는 쿠팡/네이버식: 공개 오퍼(가게 리스팅)마다 카드 한 장. 대·중·소 분류가 아니다. 가게·가격을 카드에 보여 준다.
5. 검색(`/?q=`) 뒤에도 같은 세 축으로 좁힌다. 1차로 들어왔으면 세 축 모두 그 L1 범위 안.
6. 목록·패싯·오퍼 API는 `l1_tags` 교집합이다. 1차 밖에서 브랜드/메뉴 문자열만 맞추지 않는다. 알 수 없는 `l1Tag`는 빈 결과.

URL: `/`, `/?l1=라면/면류`, `/?l1=…&axis=brand|menu|seller`, `/?l1=…&brand=` / `&menu=`, `/?l1=…&storage=상온|냉장|냉동`, `/?l1=…&all=1`, `/?q=…&axis=brand|menu|seller`

## 저장

`catalog_products.l1_tags[]` (15개 중 0~N). 제목·브랜드·기존 중·소분류·보관으로 자동 태깅. high만 자동 저장, mid/low는 MD 승격 칩에서 고친다.

구현: `apps/api/app/services/guest_l1.py`
