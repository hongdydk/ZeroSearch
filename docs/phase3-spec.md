# Phase 3 — 판매자·관리자 기능 추가

**상태:** 추후 (미착수). 이 문서는 방향 SSOT 스텁이다. 상세 API·라우트·DoD는 착수 Plan에서 확정한다.

**제품:** [제로 서치](./README.md) — 기존 `/seller`·`/admin` 포털을 키운다. 멤버십·토스 PG는 범위 밖 (PG는 [Phase 4](./phase4-spec.md)).

## 목표 (방향)

Phase 2에 이미 있는 입점·오퍼·주문 줄 배송을 **운영하기 좋게** 보강한다.

1. **판매자 (`/seller`)** — 오퍼·주문 관리를 더 풍부하게 (목록·필터·상태 전이 UX, 재고·노출 운영에 필요한 최소 필드). 제목만으로 카탈로그를 만들거나 없는 품목을 insert 하는 구멍은 메우거나 넓히지 않는다 ([README](./README.md) 「대표 상품은 누가 만드나」).
2. **관리자 (`/admin`)** — 입점 승인 너머 카탈로그·운영: `catalog_products` 조회·보정, 판매자·주문 운영, CSV/`aihub-catalog`와 맞추는 비상 경로. MD가 identity를 정하는 원칙은 유지.
3. Phase 2 공개 구매 플로우(목록·상세·장바구니·크레딧 주문)는 깨지 않는다. 결제는 계속 크레딧 스텁.

## 범위에 넣지 않음

- 토스·실 PG·웹훅 → [phase4-spec.md](./phase4-spec.md)
- 멤버십, 입점 정산·수수료, 택배사 API, 외부 크롤

## 착수 시

활성 스펙으로 올리고 Plan에 허용 경로·짧은 DoD를 고정한다. 엔티티·라우트 표는 그때 본문에 채운다.
