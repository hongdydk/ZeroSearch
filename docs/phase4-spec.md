# Phase 4 — 실 PG (토스)

**상태:** 추후 (미착수). 예전 로드맵의 「Phase 3 토스」가 여기로 옮겨졌다.

**제품:** [제로 서치](./README.md) — 지금 크레딧 스텁 결제를 **토스페이먼츠**로 교체. 웹훅·결제 상태 정합이 핵심.

## 목표 (방향)

1. 구매자 체크아웃에 토스 결제 연동 (테스트 → 운영).
2. 결제 승인·실패·취소에 맞는 주문·결제 기록 상태. 실패·취소 시 장바구니 유지·재고 반환.
3. 웹훅 수신·검증·멱등 처리. 동일 결제/승인 재시도에 중복 과금·중복 주문 금지.
4. **결제 상태 정합성** — Phase 2 「크레딧 동시성」 스텁을 대체. 승인·웹훅·클라이언트 재시도가 한 결제에 수렴.

## 선행/병행: 배송지·주문 취소·환불

“산다”를 닫기 위한 슬롯. Phase 3(판매자·관리자) 이후, 토스 PG **직전 또는 병행**. 엔티티·라우트는 착수 시 Plan에서 채운다. 택배사 API는 범위 밖 ([README](./README.md) 「범위 밖」).

## 범위에 넣지 않음 (이 phase 스텁 기준)

- 판매자·관리자 포털 확장 → [phase3-spec.md](./phase3-spec.md)
- 멤버십, 입점 정산 본업

## 착수 시

활성 스펙으로 올리고 Plan에 허용 경로·짧은 DoD·시크릿 취급을 고정한다. API·Flutter 라우트 표는 그때 본문에 채운다.
