# 프로젝트 컨셉 — 제로 서치 (Zero Search)

**읽는 사람:** 기획·UI·구현·Agent  
**성격:** 제품 방향 SSOT (기능 명세는 `docs/phaseN-spec.md`)

---

## 한 줄

**제로 서치 (Zero Search)** — 검색·목록 **중복을 줄이는** 공식·입점 마켓플레이스.

「생수」·「떡갈비」처럼 **종류(카테고리·검색어)** 로 들어가면, 목록에는 **회사+유형+품목 카드가 쭈르륵** 나온다. 생수 → 백산수·평창수…, 떡갈비 → 농심 떡갈비·매일 떡갈비. 한 장으로 모으는 것은 **그 회사의 그 품목의 용량·판매자 N장**이다. 카드에는 **단위당 대표가(중위)** 만 보이고, 용량·맛·가격·판매자 차이는 상세 **한 줄 비교**에서 고른다. **최저가·「~」 표기는 목록에 없다.**

주력은 **제조·브랜드가 밖에서 같은 정형 공산품**이다. 옷처럼 판매자가 이름만 바꿔 다른 상품이 되는 비정형은 이 목록 단위가 성립하지 않아 주력이 아니다.

쿠팡·네이버를 그대로 복제하거나 물류·광고 규모로 겨루는 프로젝트가 아니다.

---

## 사업 모델 방향

초기 기획에서 **두 갈래**를 검토했다.


|     | A: 크롤링·가격비교                           | B: 자체 몰·마켓플레이스                   |
| --- | ------------------------------------- | -------------------------------- |
| 데이터 | 외부몰 크롤·제휴                             | 자체 `catalog_products` + 공식·입점 오퍼 |
| 거래  | 외부 링크·제휴                              | 앱 내 장바구니·결제                      |
| 리스크 | 약관·가격 freshness·외부 구매 왕복·네이버식 숍 N장 나열 | 카탈로그 채우기 속도                      |


- **검토했던 대안 (A):** 외부몰 크롤·가격비교형(다나와·네이버 쇼핑에 가까움). SKU를 빠르게 채울 수 있으나, 이용약관·가격 freshness·외부 구매 왕복·네이버식 숍 N장 나열과 **제로 서치 UX가 충돌**한다.
- **확정 (B):** 자체 카탈로그 + 공식(`platform`)·입점(`merchant`) 오퍼. 앱 내 장바구니·결제·주문 줄·배송 상태까지 **한 몰에서 책임**진다.
- **공통 UX:** A·B 모두 「생수」·「떡갈비」 검색·카테고리 진입 → 그 종류 안 **회사+품목 카드가 여러 장**(각 품목 대표 1장 + 대표가). 정보 구조는 같고, **데이터·거래 주체**만 다르다.
- **향후:** MVP는 B만. 외부 참조가·하이브리드는 **범위 밖·미결** — 재검토 시 이 섹션을 갱신한다.

## 제로 서치가 겨냥하는 것


| 문제                     | 방향                                           |
| ---------------------- | -------------------------------------------- |
| 같은 회사의 같은 품목이 용량·판매자마다 카드 N장 | **회사+유형+품목당 대표 1장** |
| 검색·카테고리는 종류(생수·떡갈비) | 목록은 **품목 카드가 쭈르륵** (백산수·평창수… / 농심 떡갈비·매일 떡갈비…) |
| 목록에서 가격 비교             | 카드에 **단위당 대표가(중위)** 만 — 최저가·「~」 없음           |
| 맛·용량 차이                | **옵션 필터**(flavor, volume) + 상세 **오퍼** 한 줄 비교 |
| 용량·판매자·가격 차이           | 상세에서 **오퍼** 한 줄 비교, 나머지는 더보기                 |
| 공식·입점 혼재               | 한 목록에 두되, 가게마다 카드를 늘리지 않음                    |
| 배송 주체                  | 자사배송 / 판매자배송, 줄 단위 상태 (버튼·폴링, 택배 API 없음)     |

## 범위 밖

- **외부 크롤·가격비교를 주 사업 모델로 두는 것** (제휴 링크아웃·다나와/네이버 쇼핑형)
- 택배사 API, 권역·도착 보장 물류
- 쿠팡·네이버급 SKU·광고·최저가·쿠폰
- 입점 정산·수수료·세금
- **멤버십** (코드에 스텁이 남아 있을 수 있으나 제품 범위 아님)
- 카드 본인인증·정산까지 갖춘 운영용 결제
- **서브도메인으로 관리자·판매자를 쪼개는 것** (`admin.` / `seller.` 호스트) — 호스트는 `mall.anoveli.com` 하나. 나눌 것은 **로그인 진입점**이다.

## 역할별 로그인 (호스트는 하나)

**도메인 분리가 아니다.** 구매자 몰·판매자 센터·관리자는 같은 `mall.anoveli.com` 이다.

나눌 것은 **어디서 로그인하느냐**다. 쇼핑몰 메인에서 한 번 로그인하고 메뉴로 `/admin`·`/seller`에 들어가는 방식은 쓰지 않는다.


| 역할  | 진입        | 로그인                       |
| --- | --------- | ------------------------- |
| 구매자 | `/`       | 구매자 로그인                   |
| 판매자 | `/seller` | **판매자 로그인부터** (그 화면에서 시작) |
| 관리자 | `/admin`  | **관리자 로그인부터** (그 화면에서 시작) |


**현재 구현:** 구매자 `/login`, 판매자 `/seller`·관리자 `/admin`에서 각각 로그인. 몰 메뉴로 포털에 들어가지 않는다.

## 용어 (phase 스펙·구현)


| 용어           | 뜻                                                                                   |
| ------------ | ----------------------------------------------------------------------------------- |
| **검색어·카테고리** | **종류**. 예: 「생수」「떡갈비」 — 목록 카드 제목이 아님 |
| **대표 상품**    | 그 종류 안의 **회사+유형+품목** 카드. 예: 생수 안 「백산수」「평창수」, 떡갈비 안 농심·매일 |
| **오퍼**       | 대표 상품 + 가게 + 용량·규격 + 가격 + 재고. 실제로 담고 결제하는 단위                                        |
| **대표가**      | 해당 대표 상품 공개 오퍼 집계 **중위값**. `volume_ml` 있으면 단위당(L당), 없으면 크레딧 median. **목록 카드 유일 가격** |
| **단위당 가격**   | `price_credits / volume_ml`. 생수 등 용량 비교용                                            |
| **옵션 필터**    | 맛(`flavor`)·용량(`volume_ml_min/max`) — 집계 전 오퍼 필터                                    |
| **주문 줄**     | 한 결제 안에서 오퍼·가게별로 나뉜 줄                                                               |




### 예시

```
검색·카테고리: 「생수」 + flavor=레몬 (선택)
  → 목록: 백산수 | 평창수 | …   ← 회사+품목 카드가 쭈르륵 (각 1장, L당 대표가)

상세: 백산수
  → 오퍼: 500ml×20 공식 12,000 | 2L×6 청정마트 9,800 | 레몬 500ml×20 …

검색·카테고리: 「떡갈비」
  → 목록: 농심 떡갈비 | 매일 떡갈비 | …   ← 회사+품목 카드가 쭈르륵 (각 1장)

상세: ○○떡갈비
  → 오퍼: 500g 공식 … | 1kg 입점 …
```

## Agent·구현 기준

1. 종류(생수·떡갈비) 목록은 **회사+유형+품목 카드가 여러 장**. 카드 1장은 **그 품목**의 용량·판매자 중복만 줄인다.
2. 목록 카드 가격은 **단위당 median 대표가만** — **최저가·min_price·「~」 금지**.
3. 상세 기본 UI는 **오퍼 한 줄 비교**. 개별 최저가는 오퍼 줄에서만 확인.
4. Phase 스펙 = 만들 계약. 이 문서 = **왜·무엇을 줄이는지**.
5. 새 기능 제안 시: **같은 회사·유형·품목 카드 중복을 줄이는지** 먼저 본다.
